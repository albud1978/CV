## [Unreleased]

### Добавлено
- **Разбиение датасета по видео (train/val/test)** (`configs/dataset_split.yaml` + `src/pipeline/build_dataset.py`): зафиксированы 9 видео с обогревателями (заказчик дал окна присутствия объекта). Принцип — split по ВИДЕО, не по кадрам (иначе утечка между train/test). Для стационарных камер каждая локация (кам50, кам52, Ст2-1-4У, Стоянка9) есть в train, а в val/test вынесены отдельные съёмки тех же камер в новых условиях (ночь/дождь/вечер) — честная оценка обобщения под прод. Итог: train=6 (v01,v06,v08,v11,v13,v21), val=1 (v10 ночь), test=2 (v12 дождь, v22 вечер). Драйвер `build_dataset.py` режет позитивы ВНУТРИ окон присутствия (initial+motion) + добор негативов вне окна, штампует `split`/`video_id`, раскладывает по `<out>/<split>/<video_id>/` и пишет единый манифест. Поддержано «резюме» (`--force` для пере-нарезки) — готовые видео пропускаются.
- **Ограничение анализа движения окном присутствия** (`src/utils/motion_detect.py`, параметр `max_frame`): MOG2 декодит видео только до конца последнего `positive_window_sec` (+буфер), а не весь файл. Это кратно ускоряет ingest длинных видео (часть из них >70 мин) и обходит зависания на повреждённых GOP в хвосте (наблюдались `h264 mmco unref short failure`); добавлен пропуск до 30 битых кадров подряд без падения.
- **Ремонт битых видео перед нарезкой** (`src/pipeline/build_dataset.py`, флаг `--repair`): `cv2.read()` на повреждённом GOP не возвращает False, а БЛОКИРУЕТСЯ в декодере (вечное зависание). `--repair` прогоняет видео через ffmpeg (`-fflags +discardcorrupt -err_detect ignore_err`, только нужный отрезок) в чистый mp4 (`data/_repaired/`), который OpenCV читает без зависаний. Кэшируется. Страховка для будущих битых записей.
- **Датасет heater собран** (`data/dataset_heater/`, 9 видео): итог **831 кадр** — train 566 (v01,06,08,11,13,21), val 85 (v10 ночь), test 180 (v12 дождь, v22 вечер). Раскладка `<split>/<video_id>/`, манифест `frames_manifest.jsonl` (видео/split/source/timestamp), без утечки между split.
- **Многопроходная одноклассовая авто-разметка** (`src/pipeline/autolabel_rf.py`): решает слипание/подмену классов SAM 3. Отдельные проходы `{hose}` (136 масок) и `{person}` (105) на 48 кадрах видео 01, офлайн-слияние с разделением `person`→`staff`/`passenger` по цвету жилета (несколько HSV-диапазонов: лайм+оранжевый) и фильтром толщины маски для `wide_hose`. Экспорт в COCO instance-seg + QA-отрисовка (`data/rf_test_v2/merged/`). Результат: staff 49, passenger 56, wide_hose 68. Подтверждено: раздельные проходы устраняют слипание person+hose. Выявлено: одноклассовый `hose` жадно ловит наземные кабели (нужен пространственный фильтр «рядом с unit/брюхом»); требуется проход `unit`.
- **Якорь шланга = unit (пространственный фильтр)**: по уточнению заказчика шланг всегда рядом с обогревателем (юнитом), не обязательно с ВС. Добавлен проход `{unit}` (SAM 3 seg, промпт `generator` — точно садится на тележку, recall ~половина кадров) и фильтр в `autolabel_rf.py`: `wide_hose` остаётся только если рядом с `unit` (proximity_px из `heater_complex`); если юнит в кадре не найден — шланг сохраняется (recall). Результат на 48 кадрах: unit 23, wide_hose 68→52 (ложные наземные кабели вдали от юнита отсеяны), staff 34, passenger 71. Многодиапазонная классификация жилета (лайм+оранж) включена.
- **Операционная заметка Roboflow**: из-за дедупликации кадров по контенту проходы-проекты в UI **взаимно перезаписываются** (последний autolabel виден во всех) — для ревью нужен ОДИН проект с уже объединённой разметкой (загрузка COCO через `images_prepare_upload_zip`). Локальный merged-датасет при этом корректен (выгрузка после каждого прохода).
- **Переход на instance-segmentation + чистая перезагрузка разметки**: удалены старые detection-проекты-зонды (через REST DELETE, т.к. в MCP нет delete-инструмента), создан проект `ban-nzbro/gse-heater-seg`. Нарезаны 48 кадров со ВСЕГО видео 01 (70 мин, шаг ~89 c — попадают сцены подключения/высадки) и размечены SAM 3 в режиме масок (polygon, онтология `{generator, hose, person}`): 125 масок. Ключевой результат: **`hose` в seg-режиме даёт 1 чистую маску/кадр точно по форме широкого гофрошланга** (в detection «hose» давал кашу из вложенных боксов) — сегментация подтверждена как правильный выбор; толщину шланга мерим по маске (~15px) для отстройки от тонкого кабеля. Шланг присутствует первые ~42 мин (= факт подключения). Зафиксированы дефекты для доработки: `generator` в seg-режиме дал 0 (для unit нужен промпт `cart`/`machine`), `person` ловит пассажиров у двери. Онтология обновлена под сегментацию.
- **СЛОЙ 2 Auto-Label через Roboflow + SAM 3 (облако, MCP)**: собран и протестирован сквозной пайплайн разметки на первых 10 кадрах видео 01. Поток: `projects_create` → `images_prepare_upload` + curl-загрузка с WSL-диска → `autolabel_start` (model=`sam3`, foundational) → `autolabel_job_get` → выгрузка геометрии боксов через REST и локальная отрисовка (`data/rf_test/labeled/`). Проект `ban-nzbro/gse-apron-heater-detection`. Результат: 47 боксов на 10 кадрах за один прогон. Артефакты разметки пишутся на WSL ext4 (`data/`), не в Nextcloud.
- **Подбор промптов SAM 3 (PCS) для наземного юнита** (3 прогона на тех же 10 кадрах + скрин реального объекта): SAM 3 крайне чувствителен к слову. Итог широкого зонда одиночными существительными (conf 0.15): **`generator` → ровно 1 чистый бокс на юните в каждом кадре** (победитель для самого юнита); `hose` срабатывает мощно, но переловливает (трещины/кабели) — нужен порог ~0.5; `cart`/`trailer` ловят юнит на тесном кропе; `person`/`worker` — для кадров с персоналом. Шум: `engine`/`vehicle` (двигатели/винты ВС, бокс на весь самолёт), а фразы-словосочетания («air conditioning unit», «machine on wheels», «flexible air duct», «worker in safety vest») дали 0. Рекомендуемая онтология объекта: `{unit: "generator", duct: "hose"(conf~0.5), worker: "person"}` + ручной гейт G1. Проекты-зонды: `gse-heater-probe`, `gse-noun-probe`.
- **Онтология задачи heater** (`configs/ontology.gse_heater.yaml`): уточнённая заказчиком постановка — детектируем не «обогреватель», а **факт подключения/отключения широкого гофрошланга к ВС**. `heater` = будка/тележка на колёсах (`unit`) + **широкий гофрошланг** (`wide_hose`), подключённый к самолёту; наземный источник питания (GPU) выглядит так же, но имеет **тонкий кабель** (дискриминатор). Заданы атомарные классы (unit/wide_hose/cable/person), производные сущности (`heater_complex`, `connection_state`) и события `hose_connected`/`hose_disconnected` с антидребезгом. Зафиксирована стратегия autolabel: «generator»→unit, «hose»+гео-фильтр→wide_hose, «cable» отдельным проходом.
- **Эмпирика SAM 3 PCS (Roboflow Auto Label), 4 прогона**: (1) промпты для одного объекта конкурируют → NMS схлопывает всё в один класс («cable» монополизировал тонкие, hose-фразы дали 0); промпты разных объектов (generator+hose+person) уживаются. (2) Одинаковые кадры дедуплицируются Roboflow по контенту (общий id на воркспейс) → повторный autolabel **перезаписывает** аннотации общей записи (важно для серий — нужны уникальные кадры/чтение результата сразу). (3) Гео-фильтр по толщине бокса (min_dim 40–140, aspect 1.3–5) — путь к отделению широкого шланга от кабелей.
- **Инструкция по локальному SAM 3 / SAM 3.1** (`docs/SAM3_LOCAL_SETUP.md`): развёртывание учителя на RTX 5090 (CUDA 12.8/Blackwell, `autodistill-sam3`, веса через `ROBOFLOW_API_KEY`), пример авто-разметки папки, дистилляция в RF-DETR, подсказки по промптам PCS и лицензия SAM.
- **СЛОЙ 2 Бейк-офф учителей** (`src/pipeline/teacher_bakeoff.py`): сравнение open-vocabulary моделей-учителей на наборе кадров через transformers (без тяжёлых сборок). Поддержаны Grounding DINO (Apache 2.0) и Florence-2 (MIT). Прогон на объекте «наземный кондиционер ВС» (видео 01): Grounding DINO — мультикласс (unit/person/hose) conf~0.43, шумит; Florence-2 — точный плотный бокс по объекту. Найдена и обойдена несовместимость Florence-2 с transformers 4.57 (greedy + use_cache=False).
- **СЛОЙ 1 Ingest — motion-driven нарезка** (`src/pipeline/ingest.py`): переработан под статичные камеры наблюдения. Логика «начальная сцена (initial) + наборы по движению (motion via MOG2)»: переиспользует `MotionDetector`, сэмплирует кадры внутри событий движения с `motion_fps`, мягкий pHash-дедуп. Манифест расширен полями `source`, `event_id`, `motion_score`. Проверено на видео `01` (400 кадров, 13 событий движения, целевой объект — наземный кондиционер ВС — уверенно попадает в выборку).
- Зависимости пайплайна в `requirements.txt`: `pyarrow`, `scenedetect[opencv]`, `imagehash`.

### Исправлено
- **Тихая потеря кадров при нарезке** (`src/pipeline/build_dataset.py`): `cv2.imwrite` в `output/` (Nextcloud-монтирование `/mnt/c` через drvfs) из долгоживущего процесса молча возвращал `False` — манифест писался, но 0 jpg на диске. Исправлено: запись через `cv2.imencode`+`Path.write_bytes` с проверкой результата (кадр считается сохранённым только при наличии непустого файла), вывод по умолчанию направлен на ext4 (`data/`), как и прочие рабочие артефакты проекта.
- **Docker mount под Docker Desktop/WSL** (`.env`): bind-mounts `input`/`output` указывали на «голые» Linux-пути, невидимые VM Docker Desktop → `/app/input` был пустым. Исправлено по образцу рабочих проектов: `CV_INPUT_PATH=./input` (транслируется в UNC), `CV_OUTPUT_PATH=/mnt/c/.../Nextcloud/CV/output`. Бэкап старого `.env` сохранён.

### Добавлено (архитектура)
- **Архитектура CV-конвейера** (`docs/PIPELINE_ARCHITECTURE.md`): финальная 5-слойная архитектура авто-разметки и обучения (Ingest → Auto-Label → Human Review → Version+Train → Eval+Deploy) с гейтами G0/G1/G2, контрактами данных и картой инструментов Roboflow MCP по слоям. Решение по разработке — без мультиагента для MVP.
- **Контракты данных** (`configs/`): `task.example.yaml`, `ontology.example.yaml`, `augment_conservative.yaml` — шаблоны постановки задачи, онтологии классов и консервативной политики аугментаций (imgsz=1280, close_mosaic=10, mixup/erasing=0).
- **Правило проекта** (`.cursor/rules/cv-pipeline.mdc`): зафиксированы стандарты обучения, выбора моделей, лицензий и split (70/20/10 stratified by video_id).
- **СЛОЙ 1 Ingest** (`src/pipeline/ingest.py`): извлечение кадров через PySceneDetect (AdaptiveDetector) + дедупликация по perceptual hash + генерация `frames_manifest`. Graceful fallback при отсутствии опциональных зависимостей.
- **Roboflow MCP**: подключён в Cursor (`~/.cursor/mcp.json`, streamable HTTP `https://mcp.roboflow.com/mcp`) — даёт доступ агенту к инструментам Roboflow (проекты, датасеты, разметка, обучение, Workflows, Universe). Глобальная конфигурация MCP восстановлена из бэкапа.
- **Детекция движения** (`src/utils/motion_detect.py`): автоматическая нарезка видео на клипы с движением
  - Background Subtraction (MOG2) для обнаружения движения
  - Настраиваемый буфер после прекращения движения (по умолчанию 60 сек)
  - Объединение близких сегментов
- **Видео-пайплайн YOLO**: обработка видео с детекцией, сегментацией и трекингом
  - Детекция объектов (YOLOv8l) → `output/yolo_video/annotated_result.mp4`
  - Сегментация (YOLOv8l-seg) → `output/yolo_video/segmented_result.mp4`
  - Трекинг с траекториями и стрелками направления → `output/yolo_video/tracking_named.mp4`
- **Авторазметка кадров**: тестирование YOLOv8 и RF-DETR на извлечённых кадрах
  - YOLOv8l → `output/test_yolo/` (labels + visualized)
  - RF-DETR Small → `output/test_rf_detr/` (labels + visualized)

  - Обновлен скрипт `src/utils/download_models.py`: добавлена функция кэширования процессоров Molmo 2.
  - В `src/inference/molmo2.py` подтверждена поддержка новых моделей `Molmo2-4B`, `Molmo2-8B` и `Molmo2-VideoPoint-4B`.
