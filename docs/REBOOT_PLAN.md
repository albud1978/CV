# Перезагрузка конвейера heater: от слов к локальной модели и тайм-кодам

> Одна страница, по которой можно запустить всё с нуля. Архитектурный контекст —
> `PIPELINE_ARCHITECTURE.md`, продовый инференс-стек — `REFERENCE_ARCHITECTURE.md`.

## 1. Что требовалось

1. Максимальная **авто**-разметка на примере обогревателя: вход — слова, выход — датасет.
2. Максимально быстрый путь до **детекции**, затем — логика **«шланг подключён к ВС»**.
3. На выходе — **локальная YOLO**, в идеале работающая on-edge (телефон).
4. Разовое обучение на внешних ресурсах допустимо; брак в разметке допустим.

## 2. Пять решений, на которых стоит перезагрузка

| # | Решение | Почему так |
|---|---|---|
| 1 | **Учитель локальный, Roboflow — для ревью/версий/обучения** | Roboflow дедуплицирует кадры по контенту на весь воркспейс: повторный auto-label ПЕРЕЗАПИСЫВАЕТ аннотации общей записи. Это ломает многопроходную схему в корне (в воркспейсе уже 9 проектов с взаимно затёртой разметкой). Локальный учитель на RTX 5090 снимает и это, и round-trip'ы. |
| 2 | **Сегментация, а не bbox — но detect-ветка бесплатна** | Рукав изогнут по диагонали: axis-aligned bbox покрывает пустоту и перекрывает всё. Маска даёт и форму, и толщину (`2S/P` — отстройка широкого шланга от тонкого кабеля GPU), и КОНЦЫ рукава, без которых нет логики подключения. При этом `to_yolo.py --task detect` выводит bbox из той же разметки: «сначала детекция» не требует отдельной работы. |
| 3 | **Автоматический QA вместо сплошного ручного ревью** | 7 правил отбрасывают брак по проверяемым признакам, причина каждого отброса пишется в `rejections.jsonl`. Человек смотрит не 831 кадр, а сводку причин и выборку QA-картинок. |
| 4 | **Временная консистентность — главный множитель** | Камеры статичные. Маска, мелькнувшая в одном кадре, — почти всегда ложная; юнит, пропущенный в одном кадре, стоит там же. Треки дают и чистку, и добор меток бесплатно. Люди из этого правила исключены. |
| 5 | **Приёмка по событиям, а не по mAP** | Заказчику нужны два тайм-кода. Модель с mAP 0.9 и дрожащим состоянием хуже модели с mAP 0.8 и устойчивым. Эталон уже есть: `positive_window_sec` в `dataset_split.yaml`. |

## 3. Что нового появилось в коде

```
src/pipeline/
  ontology.py     онтология как типизированный контракт (валидация при загрузке)
  geometry.py     толщина 2S/P, вытянутость, расстояние до ребра, концы рукава, mask-IoU
  teacher.py      СЛОВА -> МАСКИ: одноклассовые проходы, backend local|stub
  fuse.py         слияние проходов -> person split -> авто-QA -> треки -> COCO
  autoqa.py       7 правил отбраковки + журнал причин
  link.py         треки по времени: голосование против мигания, добор пропусков
  to_yolo.py      COCO -> YOLO (detect|segment), split по видео, негативы
  train.py        YOLO11-seg + metrics.json + model_card.md + гейты
  export_edge.py  ONNX / NCNN / TFLite-int8 + замер задержки
  relation.py     покадровая оценка «рукав подключён к ВС»
  events.py       окно + гистерезис + склейка эпизодов -> тайм-коды
  run_video.py    продовый прогон видео -> events.json + overlay.mp4
  eval_events.py  приёмка по событиям против окон присутствия
tests/test_pipeline.py   28 тестов на синтетических сценах (без данных и GPU)
```

Единственный конфиг, который нужно править для новой задачи, — `configs/ontology.*.yaml`.

## 4. Конвейер целиком

```bash
# 0) кадры (уже сделано: 831 кадр, 9 видео, split по видео)
python -m src.pipeline.build_dataset --config configs/dataset_split.yaml \
    --output data/dataset_heater --repair

# 1) СЛОВА -> МАСКИ. Одноклассовые проходы: hose, generator, cart, airplane, person, cable
python -m src.pipeline.teacher --frames data/dataset_heater \
    --ontology configs/ontology.gse_heater.yaml --out data/labels_v1/passes

# 2) слияние + авто-QA + треки -> COCO
python -m src.pipeline.fuse --passes-dir data/labels_v1/passes \
    --out data/labels_v1 --qa-limit 60
#    смотрим: fuse_summary.json (kept_ratio, per_class) и rejections.jsonl (что срезали)

# 3) YOLO-датасет. Быстрая проверка: detect. Продовый: segment
python -m src.pipeline.to_yolo --coco data/labels_v1/annotations_coco.json \
    --frames data/dataset_heater --out data/yolo_heater --task segment

# 4) обучение (RTX 5090 или внешний GPU — разово)
python -m src.pipeline.train --data data/yolo_heater/data.yaml --task segment \
    --arch yolo11s-seg --out runs/heater_v1

# 5) экспорт под телефон + замер
python -m src.pipeline.export_edge --weights runs/heater_v1/train/weights/best.pt \
    --formats onnx ncnn tflite --imgsz 640 --data data/yolo_heater/data.yaml --int8

# 6) события по видео и приёмка
python -m src.pipeline.run_video --weights runs/heater_v1/train/weights/best.pt \
    --video "input/Видео Рощино 23.04.25/01_....mkv" --out data/events/v01 --fps 1 --save-video
python -m src.pipeline.eval_events --events data/events --split-config configs/dataset_split.yaml
```

Всё вместе — `./scripts/reboot_heater.sh` (шаги 1–4 с одним прогоном).
Сухой прогон без весов и GPU: добавить `--backend stub` в шаге 1.

## 5. Как устроена логика подключения

```
маски кадра
   |
   v
relation.analyze_frame
   концы рукава = наиболее удалённая пара точек контура
   ближний к тележке конец -> «юнитный», второй -> «бортовой»
   расстояние бортового конца до маски ВС -> P(подключён):
       касание/перекрытие                      0.95
       ближе connection.gap_px (60 px @1280)   0.75
       дальше                                  0.15
       ВС в кадре не найдено, рукав у тележки  0.55  (резерв)
       рукава нет, техника видна               0.02
       в кадре пусто                           unknown — не голосует
   |
   v
events.detect_events
   скользящее окно hold_seconds=30 c по среднему score
   гистерезис: вход 0.60, выход 0.35 (состояние не дрожит у порога)
   склейка разрывов и отбрасывание эпизодов короче 60 c
   |
   v
{"events":[{"name":"hose_disconnected","timecode":"00:42:00","confidence":0.9}], "episodes":[...]}
```

Три детали, которые обычно ломают такие системы, закрыты явно:

* **Переход на границе записи не выдумывается.** Видео 01 начинается с уже
  подключённым рукавом — событие «подключили» не порождается, только «отключили».
* **`unknown` удерживает состояние, а не роняет его.** Персонал перекрыл камеру —
  это не отключение.
* **Пороги в px масштабируются от опорной ширины 1280.** Тот же конфиг работает
  на 1920p без перекалибровки.

## 6. Приёмка

| Гейт | Метрика | Порог | Где считается |
|---|---|---|---|
| G1 | AP учителя на golden-set (200 кадров) | ≥ 0.70 | ручная разметка + сравнение с `annotations_coco.json` |
| G2 | доля принятых инстансов (`kept_ratio`) | 0.5–0.9 | `fuse_summary.json` |
| G3 | mAP@50 студента на test (дождь/вечер) | ≥ 0.75 → цель 0.90 | `metrics.json` |
| G4 | **temporal IoU состояния** | ≥ 0.85 | `event_metrics.json` |
| G5 | **ошибка тайм-кода события** | ≤ 120 c | `event_metrics.json` |
| G6 | ложные события на видео | ≤ 1 | `event_metrics.json` |

G4–G6 — то, что показывают заказчику. G3 — инженерная диагностика.

`kept_ratio` ниже 0.5 означает, что фильтры режут полезное: смотреть
`rejections_by_reason` и ослаблять конкретный порог, а не все сразу.

## 7. Риски и что с ними делать

| Риск | Признак | Действие |
|---|---|---|
| Промпт `generator`/`cart` даёт низкий recall юнита | мало `unit` в `fuse_summary` | резервное правило по присутствию рукава уже работает; добрать проход с другим существительным (`machine`, `trailer`) |
| `airplane` не срабатывает ночью | много `fallback_hose_presence` в `frame_states.jsonl` | задать `--aircraft-zone` (полигон стоянки) на камеру — статичные камеры это позволяют |
| Изогнутый U-образный рукав | ошибочные концы маски | скелетизация вместо «наиболее удалённой пары» (`geometry.polygon_endpoints`) |
| Лицензия | продукт распространяется | Ultralytics — AGPL-3.0: нужна коммерческая лицензия ЛИБО студент RF-DETR (Apache-2.0); учитель SAM 3 — проверить Meta SAM License |
| Ночь/дождь недопредставлены | провал метрик на v10/v12 | добрать видео этих условий, split по видео сохранить |

## 8. Что дальше (по убыванию отдачи)

1. **Golden-set 200 кадров** — единственная ручная работа, которая реально нужна:
   без него G1 не измерить, а качество учителя остаётся предположением.
2. **Второй круг (self-training)**: обученный студент размечает ВСЕ кадры заново,
   расхождения с учителем — очередь ревью. Это дешевле, чем улучшать промпты.
3. **Плотная разметка через SAM 2 video propagation**: учитель на 1 кадр / 30 c,
   маски протягиваются по видео — рост объёма меток на порядок.
4. **Roboflow как витрина**: залить `annotations_coco.json` ОДНИМ проектом
   (не по проходам!) для ревью и версионирования.
5. **Телефон**: NCNN-сборка + `run_video` на кадрах с камеры — замер реального FPS.
